# Abaqus 多版本兼容与选择

本说明用于回答三个容易混淆的问题：电脑装了哪个 Abaqus、应该装哪个 abqpy、MCP 是否真的能连接。它不把“可能可用”写成“已经验证”。

## 支持状态怎么理解

- **已验证**：维护者在真实电脑上完成建模、Standard 求解、ODB 读取和中文报告，并记录成功证据。
- **候选兼容**：程序能识别版本，相关依赖也存在，但还没有维护者的完整真机证据。
- **已知不兼容**：用户/项目实测没有通过；自动流程只检测并提示，不继续安装、连接或求解。
- **当前会话探测通过**：只说明这台电脑上的这次连接可用，不会自动把整个 Abaqus 年份升级为“已验证”。

目前只有 Windows 11 + Abaqus 2021 属于项目真机验证组合。Abaqus 2022、2023、2024 和 2025 可进入检测和候选兼容流程，但必须明确标注“未完成项目级真机验证”。Abaqus 2026 已知不兼容，只保留检测提示。

## 先检查，再选择

检查顺序如下：

1. 从 PATH 和常见目录中找到第一个可用的 Abaqus 启动命令和安装路径；
2. 读取 Abaqus 发布年份；
3. 用这个 Abaqus 命令实际运行内置 Python，读取 Python 版本；
4. 检查当前项目 Python 中的 abqpy 年份；
5. 用户选择智能模式时，再检查 MCP 注册和运行能力。

当前版本不会扫描并列出电脑上的全部 Abaqus。它只自动选择第一个可用命令，因此必须把这一个命令的绝对路径、年份和内置 Python 状态展示给用户。如果用户说明装了多个版本、自动路径与预期不符或版本文字不清楚，停止自动流程，请用户明确本次目标版本及启动命令/安装路径。多版本自动枚举和选择器属于后续功能。

出现上述不确定情况时：

- 不自动安装或更换 abqpy；
- 不运行 `mcp-setup --yes`；
- 不启动 Abaqus 作业；
- 不把当前解析到的第一个命令说成电脑上唯一的 Abaqus，也不默认它就是用户想用的版本。

一次只连接一个 Abaqus MCP 桥接会话，避免两个 Abaqus 版本同时读写同一组命令和结果文件。

真正启动求解时，项目会用 `ABAQUS_BAT_PATH` 把已经检查的命令明确交给 abqpy；无界面 MCP 也会检查它即将启动的同一条命令。如果命令路径、版本或内置 Python 任一项检查失败，流程必须停止。不能因为电脑上“看起来装了 Abaqus”就在版本未知时继续启动。

## abqpy 必须匹配年份

abqpy 的主版本采用 Abaqus 年份。确认用户选择后，使用精确年份范围：

| 用户选择的 Abaqus | 建议安装 |
|---|---|
| 2021 | `abqpy==2021.*` |
| 2022 | `abqpy==2022.*` |
| 2023 | `abqpy==2023.*` |
| 2024 | `abqpy==2024.*` |
| 2025 | `abqpy==2025.*` |

不要使用无年份约束的 `pip install abqpy`，因为它可能安装与本机 Abaqus 不同年份的最新版。不要仅凭包能够导入就判定兼容，还要检查包版本的四位年份是否与用户选择一致。

从 Abaqus 2024 开始，Abaqus 内置 Python 进入 Python 3 系列；Abaqus 2024 的基线为 Python 3.10。Abaqus 2021 的本项目验证环境仍是 Python 2.7.15。跨越这个边界时尤其要运行真实脚本检查，不能假设在 Python 2.7 可用的脚本一定能在 Python 3 中直接运行，反之亦然。

### Abaqus 2026 特别限制

当本次解析到 Abaqus 2026 时，不根据年份生成或安装 abqpy，也不进入 MCP 或求解流程。只报告：“Abaqus 2026 已检测到，但用户/项目实测兼容未通过，当前自动流程禁用。”不要推测具体故障原因。待项目修复并重新完成建模、求解、ODB、报告和 MCP 能力验证后，才能考虑恢复。

## MCP 按能力探测，不按年份猜测

当前使用的第三方 Abaqus MCP 没有公开的逐年兼容矩阵，也没有要求为 Abaqus 2022、2023、2024 等选择不同发行版。因此：

- 继续安装项目固定的、可审计的 MCP commit；
- 不发明 `mcp-年份` 一类不存在的版本；
- 不因为 `codex mcp list` 显示服务器名称就宣布兼容；
- 在用户选定的真实 Abaqus 会话中逐项探测。

最低探测标准：

1. 外部 MCP 服务器可以加载；
2. Abaqus 端插件可以加载；
3. 心跳持续更新，连接检查或 `ping` 成功；
4. 至少一个只读查询成功，例如读取模型名称、零件列表或作业列表。

任何一项失败都应报告具体停在哪一层，并停止执行高权限工具。只有探测全部通过后，才能把当前状态写成“本机当前会话已连接”。执行任意 Abaqus Python、修改模型或提交作业仍需遵守各自的确认点。

## 如何升级为“已验证”

为一个新 Abaqus 年份补齐验证时，至少记录：

- 操作系统、Abaqus 年份和修订号；
- Abaqus 内置 Python 版本和 abqpy 完整版本；
- 默认矩形板的 `.sta` 成功标记；
- ODB 最大位移和最大 Mises 应力；
- 中文报告生成结果；
- MCP 心跳、`ping` 和只读查询结果。

证据通过 Pull Request 审核后，才能修改项目级版本支持表。单个用户报告“能启动”不足以改成“已验证”。
