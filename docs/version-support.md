# 版本支持表

“已验证”表示维护者在真实 Abaqus 环境中完成建模、Standard 求解、ODB 读取和报告生成，不表示厂商官方认证。“可检测/候选兼容”表示项目可以识别该年份并给出匹配依赖，但尚无完整真机证据。“已知不兼容”表示用户/项目实测未通过，自动流程只保留版本检测和清楚提示。

| 环境 | 状态 | 说明 |
|---|---|---|
| Windows 11 + Abaqus 2021 | 已验证 | 五个内置模型完整通过，包括 DLOAD 动力示例 |
| Abaqus Python 2.7.15 | 已验证 | Abaqus 2021 自带环境 |
| abqpy 2021.7.3 | 已验证 | 与 Abaqus 2021 大版本匹配 |
| Visual Studio 2019 16.4.27 | 已验证 | 提供 Abaqus 用户子程序所需 MSVC 工具链 |
| Intel Fortran 19.1.3.311 | 已验证 | DLOAD 编译、链接和 Standard 求解通过 |
| Python 3.10 | CI 测试 | 主程序最低支持版本 |
| Python 3.13 | 本机与 CI 测试 | 主程序开发环境 |
| Windows 10 | 社区测试 | 尚未完成维护者真实验证 |
| Abaqus 2022–2023 | 可检测/候选兼容，未验证 | 应安装对应的 `abqpy==<年份>.*`；仍使用 Python 2 代际的 Abaqus 脚本环境，必须真机检查 |
| Abaqus 2024–2025 | 可检测/候选兼容，未验证 | 从 Abaqus 2024 起内置 Python 进入 Python 3 系列；应安装对应的 `abqpy==<年份>.*` 并进行真实脚本检查 |
| Abaqus 2026 | 已知不兼容，自动流程禁用 | 用户/项目实测未通过；只检测并提示，不自动安装 abqpy、不连接 MCP、不提交求解。待修复并重新验证后再评估 |
| Linux | 未支持 | 当前安装器和调用流程以 Windows 为主 |

MCP 注册成功不属于版本兼容证据。新版本必须在所选 Abaqus 会话中通过插件加载、持续心跳或 `ping` 以及至少一个只读查询，才可以写成“本机当前会话已连接”；这仍不等同于项目级“已验证”。

当前体检只解析找到的第一个 Abaqus 命令，不会枚举全部安装。如果用户说明装了多个版本、自动路径与预期不符或检测不确定，流程必须停止 abqpy 和 MCP 的自动安装，由用户明确本次目标版本及命令路径；多版本枚举和选择器是后续功能。新增“已验证”组合必须在 Pull Request 中记录 Abaqus 版本、Python 版本、`.sta` 成功标记、默认示例关键结果和 MCP 只读探测结果。

自动求解只允许 2021–2025，并使用 abqpy 的 `ABAQUS_BAT_PATH` 指向已经检查的命令。MCP 无界面启动也会检查即将启动的同一命令。任何版本查询失败、内置 Python 不可用或年份不在白名单的情况都会停止，不会在版本未知时继续启动。
