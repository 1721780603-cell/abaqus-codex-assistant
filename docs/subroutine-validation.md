# 子程序验证指南

这份指南帮助初学者回答“文件已生成，接下来怎样证明它算对了”。当前有十三类案例、九种子程序：DLOAD、UMAT、DISP、DFLUX、FILM、USDFLD、UVARM、UEXPAN、HETVAL。数量不代表验证程度，也不表示覆盖全部 Abaqus 子程序。

本轮维护核对时（2026-10-28），公开安装包仍是 `v0.2.2-alpha`，第 6–13 类属于其后的 `main` 源码更新。旧 EXE、单独安装的 Skill 和最新源码不是同一个版本来源；请先确认自己实际运行哪一份。不要为了体验新案例覆盖原有配置或计算目录。

## 第 7–13 类怎样开始

1. 在最新源码应用的“子程序实验”中选一个案例和保存的父目录，由应用创建新的实验子目录。使用 `subroutine-lab` 命令时，`--output` 必须指向尚不存在的目录，不要提前创建空目录；这一步不启动 Abaqus、不占用许可证。
2. 先读包内中文 `README.md`，核对 `user.inp`、`reference.inp` 和 `.for`。`verification.md` 是人工填写的记录，不是已经通过的报告。
3. 明确本次 Abaqus 年份与启动命令，并确认许可证和匹配的 Fortran/Visual Studio 工具链。多个版本并存时不能凭默认 `abaqus` 命令猜测版本。
4. 先记录默认输入、预期量及容限。得到用户明确同意后，才按包内说明顺序运行 user 与 reference 作业；它们会占用许可证并创建计算文件。任一作业失败先排查，不重复盲跑。
5. 分别检查编译/链接记录、作业结束状态和 ODB 的目标分析步末帧。成功结束还不够；必须核对两个作业的物理量、取值位置和单位一致。
6. 把实际读取值、理论值、对照值及误差填入 `verification.md`，保留证据位置。无实际结果的栏位继续写“未测”，不能用理论值代填。

第 7–13 类不走 JSON `run` 命令。目前不提供这七类案例的自动 ODB 对比、自动成功判定或自动中文结果报告。导出只负责准备可审查的文件；读取与记录仍需人工完成。

## 每次至少记录什么

| 项目 | 记录要求 |
|---|---|
| 来源 | 源码 commit/安装包版本、案例名、是否修改默认输入 |
| 环境 | Windows、Abaqus 年份与版本、项目 Python、Fortran、Visual Studio 版本；本机完整路径无需公开 |
| 编译与状态 | user 编译/链接是否成功；user 和 reference 是否均正常结束；失败时记录首个相关错误 |
| 取值位置 | 作业名、分析步、末帧时间、节点/单元/积分点及分量；求平均时写明范围和方法 |
| 单位 | 长度、力、应力，或温度、热流的单位；热流密度和体积热源不能混用 |
| 三方对照 | 理论值、user 实测值、reference 实测值，三者分列 |
| 容限 | 计算前选定的绝对/相对误差容限及理由；不为使结果通过而事后放宽 |
| 结论与证据 | 未测/失败/待排查/本次小案例通过，附脱敏日志摘录和取值证据；不扩展为工程可用结论 |

非零理论值可同时计算绝对误差与相对误差；理论值为零或接近零（例如自由膨胀的应力）时，用带单位的绝对误差判断，不能除以零。反力和热流有方向，必须先明确分量及符号约定，不能仅比较两个正数。

力学案例重点核对 U1、S11、RF1；USDFLD 另查 FV1，UVARM 另查 UVARM1。导热案例重点核对 NT11 和 HFL，并区分节点温度与积分点热流。具体理论值及位置以所选实验包说明为准，不要拿全模型最大位移模替代轴向 U1，也不要把热流读作应力。

## 分享与下一步

验证记录先保存在本机。向社区提交时仅分享必要的脱敏版本信息、输入摘要、结果表和日志摘录；不要上传 Abaqus 商业软件、许可证信息、个人凭据、完整私有模型、ODB/CAE 或其他大型计算文件。

建议先完成 DISP 的一组默认输入与内置对照，再逐例扩展；第 6 类先阅读 [UMAT 指南](../skills/abaqus-modeling-guide/references/umat-elastic.md)。所有新增案例完成证据记录后，再评估自动 ODB 对比和新版 EXE 分发，而不是继续增加未经验证的案例。任何小案例通过都不能替代真实工程的材料标定、边界复核、网格收敛和专业审查。
