# 日常维护方式

## 维护分工

- 项目维护者：判断 Abaqus 模型、单位、边界条件和结果是否合理；
- Codex：协助修改代码、增加测试、整理 Issue、准备 PR 和发布说明；
- 社区贡献者：通过 Issue 提供可复现问题，通过 PR 提交单一范围改动。

## 建议节奏

| 周期 | 工作 |
|---|---|
| 每周或有空时 | 查看新 Issue，删除敏感附件，标记 bug/feature/documentation |
| 每月 | 审查 Dependabot PR，运行测试后合并安全更新 |
| 每个 PR | 运行 Linux/Windows CI，涉及 Abaqus API 时做本机真实验证 |
| 每个版本 | 更新变更日志、支持表、README，完成发布清单 |
| 每季度 | 检查固定 MCP commit、依赖版本、安全边界和失效链接 |

## 修改流程

```text
Issue → feature/fix 分支 → 代码与测试 → Pull Request → CI → Abaqus 人工验证 → 合并 → Release
```

不要直接在 `main` 上试验复杂改动。一个 PR 只解决一个问题，方便初学者理解，也方便出现错误时回退。

## Abaqus 版本兼容

新增 Abaqus 年份支持时，先安装对应大版本的 abqpy，再运行默认示例。必须记录 `.sta` 成功标记、最大位移、最大 Mises 应力和 Python 版本；未真实验证的版本只能标为“社区测试”或“未验证”。

## 问题处理优先级

1. 凭据或敏感数据泄露；
2. 删除、覆盖用户文件或结果错误；
3. 稳定复现的环境和求解失败；
4. 文档阻塞；
5. 新功能和界面改进。
